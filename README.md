# نظام تجربة المريض — Apex Care

نظام لتسجيل تجارب المرضى ومتابعة الشكاوى ومؤشرات الأداء لفرعَي **بريدة** و**عنيزة**.

- **الخلفية:** Node.js (Express) — تخدم الـ API والواجهة على نفس الرابط.
- **قاعدة البيانات:** Supabase (Postgres) مع RLS مقفل بالكامل؛ الخادم وحده يقرأ ويكتب.
- **النشر:** Render (ملف `render.yaml`).
- **الخصوصية:** لا تُخزَّن أسماء المرضى إطلاقاً. المعرّف هو رقم الملف + الجوال (اختياري). الجوال يظهر للموظفين مقنّعاً `05*****123`.

> هذا المشروع منفصل تماماً عن نظام الطلبات: مشروع Supabase مستقل، وخدمة Render مستقلة، ومفاتيح مستقلة.

---

## خطوات التشغيل (مرة واحدة)

### 1) Supabase
1. أنشئ **مشروعاً جديداً** في [supabase.com](https://supabase.com) (لا تستخدم مشروع نظام الطلبات). اختر أقرب منطقة متاحة.
2. افتح **SQL Editor** ← الصق محتوى `supabase/schema.sql` ← **Run**. يمكن تشغيله أكثر من مرة بأمان.
3. من **Project Settings ← API** انسخ:
   - `Project URL`
   - `service_role` key (سرّي — لا يوضع في الكود ولا في الواجهة ولا يُرسل في المحادثات)

### 2) Render
1. **New ← Blueprint** ← اختر هذا الريبو. سيقرأ `render.yaml` وينشئ خدمة باسم `apexcare-patient-experience`.
2. ضع قيمتَي `SUPABASE_URL` و`SUPABASE_SERVICE_ROLE_KEY`. قيم `JWT_SECRET` و`WEBHOOK_SECRET` تُولَّد تلقائياً.
3. **Deploy**. تأكد أن `https://<الرابط>/api/health` يرجع `{"ok":true,...}`.

> الخطة في `render.yaml` هي `starter` لأن الخطة المجانية تنام عند الخمول (أول فتح بعد الخمول يتأخر ~50 ثانية). غيّرها إلى `free` إن أردت.

### 3) إنشاء حساب الإدارة
من Render ← الخدمة ← **Shell** شغّل:
```bash
node server/seed-admin.js
```
احفظ كلمة المرور المؤقتة التي تظهر — لن تظهر مرة أخرى. (لا يفعل شيئاً إذا كان `admin` موجوداً.)

### 4) أول دخول
افتح رابط Render ← ادخل بـ `admin` وكلمة المرور المؤقتة ← سيُطلب تغييرها ← من تبويب **الإدارة** أضف الأطباء ثم الموظفين (كل موظف يحصل على كلمة مرور مؤقتة تظهر مرة واحدة).

### 5) ربط شيت الشكاوى
1. افتح شيت الشكاوى ← **الإضافات ← Apps Script** ← الصق محتوى `integrations/complaints-sheet/Code.gs` ← احفظ.
2. افتح ورقة الشكاوى نفسها، ثم شغّل الدالة `setup` وامنح الصلاحيات.
3. أدخل:
   - الرابط: `https://<رابط Render>/api/webhooks/complaints`
   - السر: قيمة `WEBHOOK_SECRET` من Render ← Environment
4. يرسل السكربت فوراً عند كل رد جديد على النموذج (إن كان الشيت مربوطاً بنموذج)، واحتياطياً كل 15 دقيقة. يُرسل فقط: رقم الملف، الجوال، الطبيب، الفرع، التصنيف، الخطورة، نص الشكوى، التاريخ — **ولا يُرسل أي عمود لاسم المريض**. إعادة الإرسال لا تكرر الشكوى ولا تمسح معالجة الإدارة لها.

### 6) البوابة الموحدة
أضف رابط النظام في البوابة الموحدة.

## الصلاحيات

| | موظف (staff) | إدارة (admin) |
|---|---|---|
| تسجيل تجربة | ✓ | ✓ |
| السجل | تجاربه فقط، الجوال مقنّع | الكل، الجوال كامل |
| الشكاوى | عرض + إضافة | عرض + إضافة + معالجة |
| مؤشرات الأداء | — | ✓ |
| الإدارة (المستخدمون، الأطباء، التصنيفات) | — | ✓ |

- الدخول باسم مستخدم + كلمة مرور. الجلسة 8 ساعات.
- 5 محاولات فاشلة خلال 10 دقائق توقف الحساب مؤقتاً.
- كل دخول (ناجح/فاشل) وكل إضافة أو تعديل يُسجَّل في `audit_log`.
- المدير لا يستطيع تعطيل حسابه أو تخفيض صلاحيته. الأطباء والتصنيفات تُعطَّل ولا تُحذف.

## نموذج تسجيل التجربة
1. رقم الملف* · الجوال · الفرع* (تلقائي من فرع الموظف)
2. الطبيب* (حسب الفرع) · تاريخ الزيارة* · الوقت* (الافتراضي: الآن بتوقيت الرياض)
3. نوع الزيارة*: كشف / إجراء / كشف وإجراء
4. تقييم الزيارة*: موظف الحجز (5 نجوم) · موظف الاستقبال (5 نجوم) · وضوح الخطة العلاجية (نعم / جزئياً / لا، و«لا ينطبق» للكشف فقط) · الطبيب (5 نجوم)
5. التجربة العامة*: إيجابية / سلبية / محايدة — السلبية تتطلب التصنيف والخطورة
6. ملاحظة عامة (حتى 1000 حرف، بدون اسم المريض)

## مؤشرات الأداء
ملخص التجارب والتقييمات · جدول الأطباء (صافي التجربة، تقييم الطبيب، وضوح الخطة، السلبيات عالية الخطورة، الشكاوى، زمن الإغلاق، علامة «عينة صغيرة» تحت 20) · جدول الفروع · توزيع النجوم · أكثر المشاكل تكراراً · حسب الساعة/اليوم/الشهر/السنة · خريطة حرارية للسلبيات · اتجاه شهري للتقييمات. كل الفلاتر (بما فيها الساعة والدقيقة) بتوقيت الرياض، ولكل رسم «عرض كجدول».

## للمطوّرين

```bash
npm ci
cp .env.example .env   # ثم املأ القيم
npm start              # http://localhost:3000
npm test               # اختبارات الوحدات والـ API (قاعدة بيانات وهمية في الذاكرة)
npm run e2e            # اختبار متصفح Playwright على 390px و1280px ← لقطات في test-artifacts/
```

| المسار | الوصف |
|---|---|
| `server/index.js` | تطبيق Express، CSP، الأخطاء، خدمة الواجهة |
| `server/auth.js` | bcrypt، JWT، الصلاحيات، حد المحاولات |
| `server/validate.js` | مخططات zod وتوحيد الجوال ورقم الملف |
| `server/kpis.js` | حساب المؤشرات (دوال نقية مختبرة) |
| `server/routes/*` | مسارات الـ API |
| `public/index.html` | الواجهة (ملف واحد، بدون build) |
| `supabase/schema.sql` | الجداول وRLS والتصنيفات الافتراضية |
| `integrations/complaints-sheet/Code.gs` | سكربت شيت الشكاوى |
| `legacy/` | النموذج الأولي على Google Apps Script (للمرجع فقط) |

الـ API: كل الردود `{ ok: true, ... }` أو `{ ok: false, error: "رسالة عربية" }`. التفاصيل الكاملة في `PATIENT_EXPERIENCE_BUILD.md`.
